# Development Rules

## Stop Rule — Clarifying Questions First

Before generating the full solution, you MUST ask me at least 3 clarifying questions about any ambiguous requirements. Do not assume my tech stack versions, deployment environment, business logic, or user behavior. Ask first, then wait for my answers.

This rule applies to every solution request, without exception.

## Solution Format

*(Applies after clarifying questions above have been answered)*

Whenever I ask for a solution, ALWAYS provide 3 options:

1. **The "Quick and Dirty" fix** — Fast, minimal changes, may have technical debt but gets the job done right now.
2. **The "Clean Code" approach** — Well-structured, readable, follows best practices, good balance of effort vs. quality.
3. **The "Over-engineered" solution** — Fully abstracted, highly extensible, production-ready with all edge cases handled, but requires more time and code.

Wait for me to select 1, 2, or 3 before generating code.
